# Graphics

Three kinds, all drawn by HyperFrames on the same timeline as his video, all visible in Studio before anything renders. Preview only until he says "render them" or "render 3 and 5" (skills/edit-short).

## The default look
The first preview is already designed like the real world, not like a motion-graphics pack. Faithful real-world UI replicas are always the default. Do not stop at logo_pop, picture, text_card, underline, or a fixed stack of title cards, stat stickers, lower thirds, and swipes.

1. On a vertical Short, read `TRANSCRIPT.txt` and list every concrete real-world thing he mentions (products, sites, UIs, numbers, documents). For each one, author a faithful high-fidelity HTML replica (part 3) and place it in the top panel (or around his face, if he chose full face; see "Layout" below). That is the first preview. He changes it with notes; notes do not render. On a YouTube video, use a side or inset panel, or a full-screen cutaway with his face returning — never over his face (skills/long-form).
2. A replica has to pass for the real thing. A mention of Google search is a real Google results page: official wordmark, search bar with the query, real-styled listings, his page missing or buried if that is the point — animated like a screen recording (typing, results loading, a highlight or zoom on the key line). The same standard applies to ChatGPT, Stripe, email, a tweet, an analytics chart, or anything else he names. Use a reference screenshot when it helps. Never substitute an abstract card, a gold callout, or a typographic sting. Show only what the real UI would show: no fake find-in-page widgets or invented chrome, and no meta labels baked into the graphic ("reconstruction", "not specified in narration", "illustrative"). Each graphic holds at least about 1.5s. Charts use plausible, believable data — not a perfectly regular made-up shape.
3. **Check the HyperFrames library first** for every graphic: `bin/kit blocks search <words>` (the thing he mentions, e.g. `google search`, `chat`, `dashboard`, `match cut`). If a block or component looks like the real UI or is a clean transition that serves it, use it (`bin/kit blocks add <name>`, then `bin/kit blocks test <name>`) instead of hand-drawing. Keep it only if it passes the quality gate below; if it looks canned (a title card, count-up stat, sticker, lower third, word swipe), build your own replica.
4. Quality gate, before you show him anything and again after every later change (his notes, a hand edit, a rebuild): stills at the in, mid, and out of every graphic. Run `bin/kit blocks test <name> --style <style>` and look at the still it prints. After `bin/kit preview`, snapshot the Studio project at those times (from the kit folder):
   `.venv/bin/python -c "import sys; sys.path.insert(0,'engine'); import render_hf; print(render_hf.snapshot(render_hf.project_dir('<job>'), [t1, t2, t3]))"`
   Then actually open and look at those PNG files. Each still must show: the graphic big, sharp and solid with little empty space, his whole face (forehead to chin) below the panel (or full frame with the graphic beside it, or a full-screen cutaway), captions at their one fixed height, and only words he says (message graphics: made-up texts, see below). If Codex's browser preview tool fails, stills are the required path — do not skip looking. Ask: would this pass for the real product, and does the frame look professionally designed? Redo any that fail, up to three tries, before the preview is considered ready. Never cover his face. The first quality pass is not enough.
5. A reference reel still wins for the look (skills/style). Build the graphics in that new style so the reel's captions and the real-world graphics live together. If he says "copy this reference video," match that reference on top of this same default quality (skills/style).
6. A plain "make a Short" or "make this a YouTube video" still gets this default look. Do not fall back to the old canned pack. Saved preferences (skills/style) layer on top and never replace these graphics or the quality gate.

## 1. The kit's own graphics
`bin/kit graphics list`:
- **logo_pop**: an app logo on a white tile. `kit draft` places YouTube/Instagram ones itself when the style has `logos.enabled`. More logos: put any good-looking PNG of that logo in `assets/logos/` (official, a clean copy, or remade; see `assets/logos/README.md`).
- **picture**: a still from his library on a white rounded card (skills/library).
- **text_card**: a short line on his highlight colour, near the top. Only for a line that adds something he doesn't say word for word.
Each manifest's `plan` line shows exactly what to put in `edl.json`. `bin/kit graphics test <name>` must print OK; look at the still it prints.

## 2. The HyperFrames library (about 450, free)
Ready-made animated pieces from the HyperFrames registry. **Blocks** are whole scenes with their own canvas (chat and app mock-ups, AI chats, charts, transitions). **Components** are pieces that fill whatever box they're given (a chat message, `type-match-cut`, highlights).
1. Find one: `bin/kit blocks search <words>` (e.g. `chat`, `google`, `match cut`). Each result says block or component.
2. Install it: `bin/kit blocks add <name>`. This is the supported registry intake (`hyperframes add <name> --json --no-clipboard` into `.cache/blocks/<name>/`). It needs the internet once; after that it is reused offline. Never block or wrap `hyperframes add` in a launcher.
3. Try it on his clip: `bin/kit blocks test <name>`. It must print OK; look at the still.
4. Place it in the plan: `"blocks": [{"name": "<name>", "at": <output s>, "dur": <s>, "data": {...}, "vars": {...}}]`.
   - **On a Short, leave `box` off.** The kit sizes it (see "Layout" below), laid out at that size so its text is sharp and readable on a phone. On long-form, `box` is where it sits, on the side he isn't on.
   - **Message graphics (iMessage threads, DMs, notifications): just make it up.** The texts in them are made-up, realistic texts from a girl, the way real iMessages read (lowercase, short, emojis, "lol", "wait who is this"). Never copy or paraphrase Matthew's script lines into the bubbles. Put them in `"data"`, e.g. `{"messages": [{"side": "incoming", "text": "wait are you the guy from the gym 😭"}, {"side": "outgoing", "text": "maybe"}, {"side": "incoming", "text": "ok you're kinda funny"}]}`. The kit skips the word check for message graphics (no flag needed), stops the preview if a text copies his script, and stops it if a library or saved message graphic still shows the texts it came with. A graphic counts as a message graphic by its name (`thread-message-stack`, `*-dm`, `*notification*` ...) or by `"kind": "messages"` on the block (use that for your own replica).
   - **Every other graphic shows his words, not the block's sample text.** Many library blocks carry demo content (e.g. `ai-chat-reveal` ships "How do I turn my HTML into real video?"). Replace it with `"data"` (the same shape as the block's `data-hf-primitive-data`) or `vars`. Only quotes or close paraphrases of what he says around that moment. No invented names, claims, or slogans. The kit checks every block's text, including words typed straight into its HTML, against `words.json` near its time and stops the preview with the lines that don't match. App chrome (Search, Delivered, Today, times) is fine; mark other chrome with a `data-ui` attribute. `"invented_ok": true` only when he asked for that exact text.
   - **It has to look real.** The kit strips blur filters, never scales a block up, lays fixed-canvas blocks out at the panel size (`"fit": "scale"` keeps the old scale-to-fit, never below 0.8), and adds the real-look restyle in `graphics/_looks/<name>.css` when there is one (`thread-message-stack` becomes a real light-mode iMessage thread). If a block still looks like a stock demo (bokeh backdrop, see-through cards, generic gradients), add a look file for it or build your own replica (part 3).
   - **Text-only canned pieces are refused**: accent underline, kinetic words, lower thirds, title cards, count-up stats, callouts, swipes, stickers. The preview stops; use a replica. `"canned_ok": true` only when he asked for that exact piece.
   - `vars` sets a block's own variables when it has them (text, colours).
   - Captions stay on top of blocks, at one fixed height for the whole video.
5. `bin/kit preview <job>` and look. It prints where each graphic went. It refuses to open while HyperFrames lint/check or the kit's layout check report any error: fix every one it prints (`bin/kit check <job>` lists them), then preview again.

## Layout on a Short (the kit places every graphic; never fight it in `index.html`)
- **Panel** (the default look): while a graphic shows, a panel on top as tall as that graphic needs (a short thread gets a short panel, so more of his face shows; never a forced half screen), his face right below it, framed between the panel and the captions. His face is full frame in the hook and between graphics. Set `"panel_h": <px at 1920>` on a block only if the kit's size is off. A `box` that reaches onto his face or the captions, or is narrower than 60% of the width, is moved into the panel (the preview says so).
- **Full face** (only when he asks, e.g. "keep my face full screen"): `"graphic_layout": "full"` at the top of that video's `edl.json`. His face stays full frame; each graphic pops in as an overlay in the space above or below his face, or as a full-screen cutaway when there's no room (`"show": "cutaway"` on a block forces that). Never on his face.
- Captions stay at one height and one size all video (long ones break onto a second line). `bin/kit check <job>` fails a hand edit that puts a graphic on his face, in the captions, makes it tiny, or a cutaway that doesn't fill the frame.

## 3. A new graphic he asks for, or that this video needs
Build it for this video only, as a block-style HTML file in that video's folder. On a creative ask you do this without waiting for him to name the graphic. The first preview should already include a replica of each real thing in the transcript.
**Never save a graphic or template into `my-styles/`, and never make a per-video style, template copy, or `frame_layout` override, unless he explicitly asks to save it to his style.** (A look change he asks for, like smaller captions, is still saved as a preference: skills/style.) A new Short starts clean: it never reuses an old video's graphic or its text.
1. Start from scratch when you are matching a real product UI, or from the closest library block only if it already looks like that UI. Put it in `.work/<job>/graphics/<name>/<name>.html` (a HyperFrames composition: a root `data-composition-id`, `data-width`, `data-height`, `data-duration`, and one paused GSAP timeline registered as `window.__timelines["<id>"]`). For a Short, design it at 1080 wide and only as tall as it needs (the panel is sized to it). Every animation must come from that timeline (no timers, no random values). **Declare its own font**: an `@font-face` inside the graphic with the font file in its own `assets/` (the page's `kitfont` is not visible to it, and HyperFrames' font check fails). Do not fetch the live product at render time; baked-in assets and HTML are fine, including a reference screenshot you saved into `assets/`.
2. Use the real product's colours, type, and layout, not only the style's `highlight_color` and `font_file`. Those style values are for captions and the frame, not for faking a Google page in Outfit and gold. Images the graphic needs go in that folder's `assets/` and are referenced as `assets/<file>`.
3. `bin/kit blocks test <name> --job <job>` must print OK. Look at the still, then run the quality gate above. The plan then uses it like any block: `"blocks": [{"name": "<name>", "at": <output s>, "dur": <s>, "vars": {...}}]` (leave `box` off on a Short). This video's graphic wins over a library block with the same name.
4. Only if he says to keep it in his style ("save this to my style", "use this every time"): `bin/kit graphics save <name> --job <job>`. That copies it into `my-styles/<style>/templates/<name>/` marked as saved; later videos may use it, always with their own words or freshly made-up texts. A graphic an older video left in `my-styles/` without that is refused by the preview. Add a line to the style's STYLE.md saying when it appears, and tell him it's saved.
